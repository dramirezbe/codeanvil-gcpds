Objective: align S0, S1 and G1 with today's paper changes, then add S2 and G2 so a project can run the whole V-SIL v3 flow to a Verified Prototype. The optional ML model is out of this round (S10).
Branch: `feat/vsil-v3-full-flow` (from `main`). Delivery strategy: `ask-on-risk`; forecast about 1,100 authored changed lines, so the chain strategy is asked before the first commit that crosses 400.
Test runner: `uv run --extra dev pytest` (skill-text assertions through `_skill_text()` in `tests/test_create.py`, contract C8).

## Shared contracts (new, on top of C0–C11)

- **D1 HAL mode.** S1's design Meta carries `HAL mode: mock-only | mock+real`. Every later skill reads it from the design; nobody asks again.
- **D2 Delivered tree and kit (S12).** Code lives in the project root, outside `.codeanvil/`. One rule for every language: **each service is `src/<service>/`**, where `<service>` is the package name from D7.
  - **Python service** (uv): a package with `__init__.py`, `__main__.py` (delegates to `main.main()`), `main.py` (base: orchestration and routing), `config/{logger,paths,runtime}.py`, `hal/` (HAL port, plus the Real HW HAL in `mock+real`), one subpackage per functional layer (`dsp/`, `decision/`, `output/`, …) and `lib/`. One root `pyproject.toml` + `uv.lock` for all Python services: packages listed explicitly (`[tool.hatch.build.targets.wheel] packages = ["src/<service>", …]`), one `[project.scripts]` entry per service, kit dependencies and pytest in `[dependency-groups] dev`, pytest configured with `testpaths` and `pythonpath` (no `sys.path` bootstrap). Deploy with `uv sync --frozen --no-dev`. A uv workspace is allowed only when two Python services deploy to different hosts with conflicting dependencies, recorded as a design decision.
  - **TypeScript service** (pnpm): a pnpm package with no nested `src/`: `package.json`, `tsconfig.json`, its entry (`main.ts`, or `main.tsx` + `index.html` + `vite.config.ts` for a UI), `config/{logger,runtime}.ts`, `hal/`, one folder per functional layer, `lib/`. Root `package.json` (private, `packageManager: pnpm`), `pnpm-workspace.yaml` (`src/*` TS services and `verification/*` TS kits) and `pnpm-lock.yaml`.
  - **Root:** `cmd/` (install and deploy scripts) and `daemon/` (systemd units) when the design deploys to a host. Root manifests exist only for the toolchains in use.
  - **Kit:** `verification/` with shared out-of-process pieces — `run.sh` (one entry per level: `run.sh vl0`, `run.sh vl1`, telemetry attached), `golden/` + `manifest.md`, `telemetry/` (the companion, a separate Python process, any service language) — and one folder per service, `verification/<service>/`, in that service's language: `mock_hal/`, `stubs/`, `fakes/`, `drivers/`, `test/` (pytest for Python, vitest for TS; a TS kit is a private pnpm package).
  - **Never shipped:** no service imports or depends on anything under `verification/` (Python: not in the wheel, dev group only; TS: no service `package.json` lists a kit package). Nexus-API conventions inside each service: type hints, Google-style docstrings, `.env.example` committed and `.env` ignored, paths resolved in `config/paths.py`. The exact trees, Python and TS, are S2's locked `references/project_layout.md`.
- **D3 Telemetry companion.** Mandatory in every design (S1 §1.7) and every test run (S2, G2). It is part of `verification/`, has no `SYS-*`, is not in the DAG and is never listed as module evidence.
- **D4 Golden vector manifest.** `verification/golden/manifest.md`, one row per vector: id, SHA-256, generation parameters, simulated condition, expected output. Changing a vector invalidates the evidence that used it.
- **D5 Levels by mode.** `mock-only` caps every claim at VL-1. `mock+real` allows VL-2, but each module or path still declares its level per cycle (S7).
- **D6 Design-defect route.** S2 and G2 never edit the design. A design defect is an iteration with `| HITL | FEEDBACK |` and the line `Verdict: design defect` naming the S1 sections to rework; S1 accepts it as a rework request, like a G1 FEEDBACK.
- **D7 Toolchain.** S1's design Meta carries one `Toolchain` entry per service: `SVC-xxx: <package> · <language> · <package manager> · <test runner>`, for example `SVC-001: fm_edge · Python 3.12 · uv · pytest; SVC-002: dashboard · TypeScript · pnpm · vitest`. `<package>` is a valid identifier and names `src/<package>/` (D2). Allowed this round: Python with uv and pytest, TypeScript with pnpm and vitest. G1 reviews it; S2 builds with it and never chooses another. An empty or incomplete `Toolchain` is a design defect.
- **D8 Test authorship.** S2 writes every test, including the VL-1 tests for modules and paths with `required_vl` VL-1 or higher, and `verification/run.sh`. `S2_artifacts/test_run.md` records exactly two commands, `verification/run.sh vl0` and `verification/run.sh vl1`, whatever the languages. G2 only runs those commands (P2: the oracle is not the generator). A missing VL-1 test is a module defect routed to S2.
- **D9 Lab inputs in the SyRS (S11).** Lab procedures go to SyRS §6 Field Measurement Protocols (`PROTO-*`: setup, calibration, execution), calibration terms to §4 Correction Chains, tolerances to §5 Uncertainty Budgets. The three headings stay required (`g0_validate.py` does not change); with no lab inputs, each holds exactly `Not applicable: no lab inputs in the Build Package.` S1 cites `PROTO-*` only in `mock+real`; `mock-only` ignores §4–§6.
- **D10 Logger (S12).** Every Python service ships `config/logger.py`, a self-contained copy of CodeAnvil's logger with **no import of `codeanvil`**: same colours (DEBUG grey, INFO magenta, WARNING yellow, ERROR red, dim logger name), same format `[YYYY-MM-DD HH:MM:SS.mmm] LEVEL name.funcName message`, stderr, `NO_COLOR` / `FORCE_COLOR`, Windows VT enable, `propagate = False`. The timestamp function is inlined; its timezone comes from `config/runtime.py` (`TIMEZONE`, default `America/Bogota`, `UTC` fallback). Every module uses `log = get_logger(__name__)`; no `print`. S2 copies it unchanged from its locked `references/logger.py`.
  Every TypeScript service ships `config/logger.ts`, copied unchanged from `references/logger.ts`: `getLogger(name)` with `debug`, `info`, `warn`, `error`; same format and timezone rule through `Intl.DateTimeFormat`, reading `TIMEZONE` from `config/runtime.ts`. In Node: the same ANSI codes, `NO_COLOR` / `FORCE_COLOR`, TTY check, stderr, and `funcName` taken from the stack trace (best effort). In the browser: the same hues through `%c` CSS, and no `funcName` (`name message`). No `console.log` outside the logger.
- **D11 Verifier subagent (S13).** `vsil-verifier`: fresh context, read-only (no edit or write tools; shell only to run the `test_run.md` commands), never writes a report and never asks the human. It returns a results table to G2, which presents it, asks for the verdict and writes `G2.md`. `codeanvil create` ships it for Claude Code, OpenCode and Codex with one shared body (T9). Runtimes without subagents (Copilot, Pi): G2 asks the user to run G2 in a fresh session.
