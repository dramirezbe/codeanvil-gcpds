# CodeAnvil v0.6.0

v0.6.0 adds a global methodology runtime, a `codeanvil python` runner, and an
MCP server manager (first server: Marconi / GNU Radio), so skill scripts and
RF/SDR tools run on a managed interpreter instead of the project's own.

## Features

- **Global methodology runtime** (`~/.codeanvil-config/runtime/`): one shared
  `uv` venv built from `config.yaml` `runtime.base` (psutil, pyyaml).
  - `codeanvil runtime sync | add | remove | list | path` — manage it; base
    packages cannot be removed.
- **`codeanvil python <script> [args]`** — run a skill script on the runtime
  with `python -I`, from the project root. On POSIX the launcher `execv`s into
  the interpreter, so the script's parent is the caller.
- **MCP server manager** — install external tool providers globally and wire
  them into projects through a portable launcher:
  - `codeanvil mcp add | update | remove | list | doctor | run | enable | disable`.
  - First server **Marconi** (GNU Radio): 19 tools + 6 RF/SDR skills. The venv
    is built on the exact system interpreter GNU Radio was compiled for;
    `doctor` names the fix for each problem, and `update` rebuilds a broken venv.
  - Per-project configs call `codeanvil mcp run <name>` — no absolute paths, so
    a project stays portable when moved.
- **`codeanvil sandbox <agent>`** launches an agent with only project-local
  settings.

## Fixes

- **Sandbox MCP isolation**: `codeanvil sandbox claude` now passes
  `--strict-mcp-config` (and `--mcp-config <project .mcp.json>` when present), so
  the claude.ai account-managed MCP servers (Claude Docs, ClickUp, Lucid, …) no
  longer leak into a sandboxed session. A project with no `.mcp.json` sees no
  MCP servers at all.
- **Telemetry collector** keeps samples on a fixed monotonic grid, so a slow
  per-sample sensor read never stretches the interval.
