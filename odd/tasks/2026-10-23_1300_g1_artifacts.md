# G1 Design Artifacts

## Objective

Each G1 job writes its output to a separate file under
`.codeanvil/report/<cycle>/G1_artifacts/`. The iterative HITL report (`G1.md`)
stays unchanged — it records verdicts, not design content. Branch: `main`.

## Specs

### S1 — Artifact folder and naming convention

G1 writes intermediate design files to `.codeanvil/report/<cycle>/G1_artifacts/`:

```
.codeanvil/report/<cycle>/
├── G0.md
├── CC.md
├── G1.md                          # HITL report (unchanged)
└── G1_artifacts/
    ├── ASR.md                     # Job 1: extracted ASRs + condition groups
    ├── Arch_01.md                 # Job 3: candidate 1
    ├── Arch_02.md                 # Job 3: candidate 2
    ├── ...Arch_NN.md              # as many as user requested
    ├── QA_matrix.md               # Job 4: quality attribute scores
    ├── ATAM.md                    # Job 5: trade study
    ├── ADD.md                     # Job 6: decomposition + dependency graph
    └── review_package.md          # Job 9: consolidated review
```

Rules:
- `Arch_NN.md` uses zero-padded two-digit numbers matching generation order.
- On rework, the artifact file is **overwritten** (not appended). The HITL
  report tracks iterations; the artifact is always the latest version.
- The agent creates `G1_artifacts/` on first write (Job 1).
- `GT/G1_SRS.md` stays as the only GT-level deliverable (Job 7). Artifacts
  are working material — auditable but not GT.
