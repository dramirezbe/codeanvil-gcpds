- Graph: `.codeanvil/report/01_fm_occupancy_mock/S1_artifacts/S1_graph.html`

Rework of four design defects identified by G2 iteration 1:

1. **Graph `hardware = []` → populated**: Added HW-001…HW-004 to the graph's `hardware` array with empty `to` arrays (mock-only, no `hw_dependency: true` modules). The graph now shows all four COTS devices from §0.1.

2. **HAL contract type clarified**: §1.3.2 now documents that the HAL port receives raw uint8 from `iq_stream.v1` and converts to complex64 using `capture.convert_samples()` before yielding `HalFrame`. The data routing table, the capture module card, and the `iq_stream.v1` contract are updated to reflect this single boundary: uint8 enters the HAL, complex64 exits it.

3. **Capture buffering strategy defined**: §1.3.2 now specifies that at 2.4 MS/s the device produces 1,200,000 samples per 0.5 s update; the HAL drains the stream into a circular buffer and extracts the most recent K×N = 65,536 samples per update. In mock-only mode the Mock HAL generates exactly K×N samples, so no buffering is needed. The `iq_stream.v1` contract's Shape field is updated accordingly.

4. **PATH-004 level consistency noted**: PATH-004 was already declared VL-1 in §4.4 (correct). The G1 report (iteration 1, line 40) incorrectly claimed a VL-0 connected-process test for it; this is a G1 reporting error, not a design defect. No design change needed; G1 will re-review.
