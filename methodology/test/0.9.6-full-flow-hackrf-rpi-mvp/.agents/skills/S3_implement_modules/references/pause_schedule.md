# Apply the S3 schedule to its admitted scope

## Enter and resume

Read the actual current SKILL.md and the applicable references into context. A command that
redirects their content to a null device is not a reload. Check G2's current scope, custody and
S2 output baselines before code. An invalid S2 report belongs to S2; an invalid or obsolete G2
belongs to G2. Load the owning skill if that repair is authorized, then return to S3 only after
its prerequisite passes. Never fix upstream reports or infer a new human verdict as S3.

Ask the pause schedule once per new iteration, unless following the fixed module-defect rework
route. A reply already present in the same conversation remains the selected schedule on resume.
Do not re-ask it just because S3.md has not been published yet. Scope checkpoints control when
to pause; they do not add prerequisites. Respect explicit stop, real permission/MCP restart,
missing contract or operational failure using the existing skill boundaries.

## Work to the next applicable checkpoint

| Admitted scope and schedule | Authorized work before the checkpoint | After continue |
|-----------------------------|---------------------------------------|----------------|
| slice 0, either option | Parent creates approved manifests, bases, kit, loggers, stubs and placeholder integration; runs the scoped VL-0 floor with telemetry. Per module is valid despite there being no module implementations. | Finish test_run/report publication and hand off to G3. Do not add module, PATH or another infrastructure pause. |
| slice k, Per module | Fresh implementor for each approved module, its unit/bottom-up/sandwich and declared development checks; parent validates returned scope before pausing after that module. | Next approved module; after the last, run the full built floor and publish evidence/report. |
| slice k, Per slice | Complete only the approved modules, their prescribed checks and the full built VL-0 floor. | Finish publication and hand off to G3. |
| system, Per module | Parent completes the approved integration and contract checks; pause before PATH tests. There are no new module-implementation checkpoints. | Run PATH, entry-point and other scoped checks, full floor and publish evidence/report. |
| system, Per slice | Same mandatory integration checkpoint before PATH tests; after continue complete all scoped checks and pause at completed system slice. | Finish publication and hand off to G3. |

Checkpoints describe completed, checked work. Selecting Per module is never an instruction to
wait before infrastructure. Do not ask for a different schedule merely because a scope has no
modules. Do not double-pause when infrastructure and the slice-completion boundary coincide.
Keep no-op units, future modules and final PATH tests out of earlier scopes.

Prepare the final floor/evidence under steps 6–7, backing up an older test_run before overwriting
it. Show actual commands, results and pending work at the checkpoint. Retain run IDs, logs and
telemetry so publication after continue does not fabricate evidence or rerun successful checks
without cause. If code or test inputs change, rerun the affected checks before claiming delivery.

Use the existing checkpoint format when publishing S3.md. Continue/rework/stop answers are
execution decisions only. At stop preserve drafts and code and write no completed iteration;
at rework fix only the named approved scope and repeat its checks before the next checkpoint.
Neither pause selection nor continue is G2/G3 PASS or hardware authorization. Only G3 system
PASS produces the Verified Prototype.
