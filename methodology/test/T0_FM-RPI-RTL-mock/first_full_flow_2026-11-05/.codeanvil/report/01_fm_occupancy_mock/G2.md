#### Verdict: design defect

All tests pass at their declared levels, but the human identified four design defects in S1 that
verification cannot cover:

1. **S1 graph `hardware = []`**: `S1_graph.html` line 49 declares an empty hardware list, although
   the design text lists four COTS devices (HW-001…HW-004). The G1 checklist (line 12) calls this
   an open finding; G1 iteration 1 marked it "ok" without resolving it.

2. **HAL contract type mismatch**: `S1_design.md` line 128 says the HAL yields `complex64`, but
   the `iq_stream.v1` contract supplies raw `uint8` bytes that `SVC-001/capture` converts. The
   design must specify one type at the HAL boundary.

3. **Capture buffering undefined**: At 2.4 MS/s × 0.5 s = 1,200,000 samples per update, the
   design passes only 65,536 (K × N) into each Welch periodogram. It does not define how the
   continuous IQ stream is drained or how the 65,536-sample window is selected from the 1.2 M
   available.

4. **G1 checklist issues**: The G1 report (line 40) claims a VL-0 connected-process latency test
   for PATH-004, but the S1 design declares PATH-004 at VL-1 only. G1 also marked the declined
   `tsc` global install as an advisory, whereas the current G1 skill treats a refused missing tool
   as an open finding.

**S1 sections to rework:** §1.5 (HAL substitution ladder — type at HAL boundary), §1.6 (module
table — capture buffering strategy), §4 (system paths — PATH-004 level consistency), and the
dependency graph generator (hardware list).
