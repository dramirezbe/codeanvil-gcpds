# UI RF Reference — Visual Design for Signal-Processing Browser UIs

Optional reference for S3 when a subsystem includes a browser UI that displays RF or
signal-processing data. This skill produces no reports and requires no verification.

## When to use

S3 reads this skill when the SDD describes a browser subsystem that renders any of:
spectrum traces, waterfalls/spectrograms, channel tables, constellation diagrams, or
time-domain waveforms. If the design has no browser UI, ignore this skill entirely.

## Inputs

| Source | What |
|--------|------|
| `.agents/skills/ui_rf_reference/references/design_principles.md` | Anti-generic design rules adapted for RF dashboards |
| `.agents/skills/ui_rf_reference/references/canvas_patterns.md` | Canvas 2D and WebGL component patterns with code |
| `.agents/skills/ui_rf_reference/references/palette.md` | RF-themed color tokens, dark-first with light variant |
| `.agents/skills/ui_rf_reference/references/layout.md` | Responsive panel layouts for 1–3 view RF dashboards |
| `.agents/skills/ui_rf_reference/references/dependencies.md` | Recommended libraries with justification |

## How S3 applies this

1. Read the design principles before writing any UI code.
2. Choose the layout from `layout.md` that matches the number of views in the SDD.
3. Apply the palette tokens from `palette.md` as CSS custom properties.
4. Use the canvas patterns from `canvas_patterns.md` as starting points, not templates.
5. Pick libraries from `dependencies.md` only when justified by complexity.

The goal is a UI that looks like it was designed by someone who works with RF equipment,
not generated by an AI. Every visual choice should come from the subject matter.
