Integration Points

Ctx 02 → DSP Pipeline: The agent-driven experiment pipeline lives inside the architecture-exploration phase of Layer 1. When Ctx 02 needs to resolve a DSP trade-study (filter topology, decimation strategy, detection threshold), the agent generates hypotheses as Python pipelines, validates them against the HardwareConstraints dataclass, and promotes winning designs to GNU Radio flowgraphs for SIL-level validation.
DSP Pipeline → Ctx 03: A promoted experiment becomes the design contract for Ctx 03 (Module Design). The experiment log provides traceability: every parameter choice links back to a measured SNR, BER, and latency on synthetic I/Q data.
PCG S1 (Sandbox) → DSP Pipeline: In Layer 3, the Sandbox stage reuses the same exploration loop for production-time tuning. Field feedback (calibration drift, interference patterns) re-enters the pipeline as new constraints, and the agent explores compensating DSP configurations without human re-engineering.

Governing Principles

P1 HITL ≠ HIL — human authorization and hardware validation are distinct barriers.
P2 Oracle ≠ Generator — the LLM drafts; external criteria decide.
P3 Mechanical rejection beats LLM approval, never the reverse.
P4 Verified ≠ Validated — claims must name the environment (SIL vs HIL).
